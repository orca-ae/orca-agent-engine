# `@orca/pi-harness`

The native Pi SDK integration pins `@earendil-works/pi-coding-agent`, `pi-agent-core`
and `pi-ai` to 1.5.0. The published dependencies pin the SDK's companion packages
to the same version. `pi_sdk` is a distinct harness identity from the older `pi`
CLI RPC provider. It implements the same [`@orca/sdk-harness`](sdk-harness.md)
worker contract used by Codex.

| Deployment                 | Execution owner | Native worker                                                                |
| -------------------------- | --------------- | ---------------------------------------------------------------------------- |
| Cloud `separate` (default) | harness-server  | Embedded Pi session in the server's private working directory                |
| Cloud `colocated`          | harness-server  | `pi-sdk` provider in the shared sandbox-harness image, over private HTTP/SSE |
| Self-hosted `colocated`    | Registry        | session-runner launches the Pi worker through `SandboxHandle.spawn`          |

Select it when creating an Agent:

```json
{
  "name": "Pi agent",
  "model": { "provider": "openai", "id": "gpt-5.4", "effort": "low" },
  "metadata": { "harness": "pi_sdk", "mode": "colocated" }
}
```

Omitting `mode` selects `separate`; self-hosted environments require `colocated`.
The model policy pins the static API-key catalogs shipped with Pi 1.5.0 for
OpenAI Responses, Chat Completions, Anthropic Messages and Gemini GenerateContent.
It retains existing Orca OpenAI aliases. `piModelApi(provider, model)` selects the
protocol per model, including providers that expose multiple protocols. The
catalog is generated by `packages/pi-harness/scripts/generate-catalog.mjs`; its
`--check` option checks the installed SDK without network discovery.
An omitted effort uses `medium` when supported, otherwise the first supported
effort (or `off` for a non-reasoning model). The Responses adapter sends the
Session-pinned value in `reasoning.effort`, including OpenAI `ultra`.

Examples include `anthropic/claude-sonnet-4-6`, `openai/gpt-5.4`,
`deepseek/deepseek-flash`, `google/gemini-2.5-flash` and `zai/glm-4.7`.
Discovery describes SDK capability; a deployment must also configure credentials,
model grants and pricing. A custom base URL never bypasses model admission.
Only explicit static API keys are accepted. OAuth login/refresh and ambient cloud
credential resolution are disabled. Providers requiring other protocols or
account/deployment discovery are excluded from the generated catalog.

### Credentials and native Gateway transport

Cloud separate reads the selected provider key from harness-server for direct
egress. Session metadata `orca_llm_egress: gateway` selects scoped Gateway egress.
Cloud colocated always uses Gateway tokens; self-hosted Gateway egress takes
precedence over direct runner credentials. The same worker handles all three modes.
Provider, model and history stay pinned; transport credentials refresh between turns.

Direct configuration retains `OPENAI_API_KEY` / `OPENAI_BASE_URL`,
`ANTHROPIC_API_KEY` / `ANTHROPIC_BASE_URL`, and `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL`.
Gemini uses `GEMINI_API_KEY` / `GEMINI_BASE_URL`; ZAI uses `ZAI_API_KEY` / `ZAI_BASE_URL`.
Other providers default to their uppercased provider ID with hyphens replaced by
underscores, plus `_API_KEY` and `_BASE_URL`. Explicit mappings override defaults:

```sh
PI_SDK_PROVIDER_CREDENTIALS='{"zai":{"apiKeyEnv":"MY_ZAI_KEY","baseUrlEnv":"MY_ZAI_URL"}}'
```

The mapping contains environment-variable names, not credentials or file paths.
`ORCA_RUNNER_ENV_PASSTHROUGH` must explicitly include these variables when
launching a self-hosted runner; environment-worker does not inherit them by default.

Pi's official provider encodes messages, tools and thinking settings. The worker
then redirects its HTTP request to `/v1/proxy/{provider}/{upstream-path}` on the
Gateway origin, preserving body bytes and provider-specific options. Upstream
authentication is removed before the request receives its scoped Orca bearer token.
The Gateway selects a configured upstream and injects its Vault-backed API key.
Real upstream keys do not enter cloud colocated sandboxes. Redirects are rejected.
The Pi Google adapter uses a token-authenticated, worker-private loopback bridge
to apply the same transport and raw usage validation.
The bridge closes with the worker and cancels active requests on interruption.

Each protocol binding uses route name `llm-pi-{provider}-{api}` and a canonical
Gateway route match `/v1/proxy/{provider}/{api}`. The actual incoming HTTP path
contains the upstream path; the Gateway derives the canonical match only after
checking its configured allowed paths. JWTs contain the exact pinned model and
its Pi route, intersected with `SESSION_JWT_LLM_MODELS` and `SESSION_JWT_LLM_ROUTES`.
Model authorization and Registry pricing both retain the logical provider ID.

The Helm `aiGateway.piProviders` list configures native destinations separately
from legacy `openai`, `anthropic` and `deepseek` routes. Each binding specifies
`provider`, `api`, `baseUrl` (upstream origin), `apiKeyEnv`, `auth`, `allowedPaths`,
and optional `allowedQueryParams`, `headers` and `forwardHeaders`.
The Pi Anthropic adapter calls the beta Messages endpoint with `?beta=true`.
The Compose generator and Helm template allow that query parameter on the native
Anthropic binding.
Provider keys are supplied through `aiGateway.extraEnv` Secret references.
Pi bindings set `emit_usage: false`: Gateway admission and spend settlement remain
active, while the SDK's durable turn accounting is authoritative for Registry billing.
Existing Claude Messages and Codex Responses endpoints retain their behavior.

For Compose, generate an explicit native configuration with:

```sh
mkdir -p services/dev/run
node scripts/render-pi-gateway-config.mjs services/dev/ai-gateway-config.yaml services/dev/run/pi-gateway-config.yaml
# In services/dev/.env, select an image containing native_api_key support:
AI_GATEWAY_CONFIG_FILE=./run/pi-gateway-config.yaml
SESSION_JWT_LLM_ROUTES=llm-pi-anthropic-anthropic-messages
SESSION_JWT_LLM_MODELS=claude-sonnet-4-6
```

The generator adds OpenAI, Anthropic, DeepSeek, Gemini and ZAI examples without
changing existing routes. `AI_GATEWAY_CONFIG_FILE` defaults to the legacy config.
Registry prices usage with the persisted provider/model and deployment price table,
never a model-supplied cost. Unpriced models cannot satisfy a USD budget preflight.

The older `pi` CLI provider uses separate npm aliases pinned to 0.87.1 for its
controlled CLI and usage-reporting adapter. Its native-completion version and
source identity remain independent of the managed `pi_sdk` dependency.

## Managed execution

`createAgentSession` uses an in-memory credential store, settings and session
manager. Its explicit resource loader contains no discovered extensions, Skills,
project context files, prompts or packages. Orca supplies the system instructions
and managed Skill catalog. Built-in Pi tools are disabled. Only the supplied
allowlist is installed as native custom tools; each call is relayed to the owning
adapter for permission checks, confirmation, sandbox execution, remote MCP or
client callbacks. The shared callback converter preserves text, inline images,
text documents and search results, and rejects unsupported sources before native
continuation.

The shared host/runner adapters enforce the Codex contracts for resources, request
budgets, stateless tool guards, required actions, events and recovery. Multiagent,
stateful tool phases and soft budget approval thresholds are rejected by the
capability catalog. Budget limits apply between turns. Auto-compaction, SDK retries
and cache warming are disabled. The adapter emits completed assistant text and
one aggregate terminal usage record for all model requests within the turn.

## Private checkpoints

Each completed turn emits a versioned checkpoint with `format: "pi_sdk"`,
`sdkVersion: "1.5.0"`, native session ID, instruction digest and a single base64
`session.json` payload. It contains native Pi session entries, the pinned provider/model
and system instructions. Validation checks the size limit (16 MiB), canonical
encoding, UTF-8, instruction digest, session identity and entry ancestry. Registry
also binds the format to the Session-pinned harness. Checkpoints never enter the
public transcript and cannot be imported as Codex rollouts.
Deploy Registry with 1.5.0 checkpoint support before starting 1.5.0 workers.
Sessions that have written a 1.5.0 checkpoint require a Registry and workers
that accept that tag to resume after a rollback.

The decoder also accepts checkpoints from 0.87.0, 0.87.1 and 1.0.4. Native session
entries remain version 3 and retain their session identity and message/tool
ancestry. Previously admitted models retain their API, endpoint and supported
efforts through the compatibility definitions in
`packages/pi-harness/src/legacy-models.json`. Previously admitted Kimi Coding
models use the native Anthropic Messages adapter at their retained endpoints.
An unsupported model from 0.87.0 still receives a versioned error directing the
caller to start a new Session with a supported model.

Cold startup reconstructs `SessionManager` from those entries. A managed Skill
policy transition must retain the base instructions and immutable Skill pins;
the caller verifies that transition before updating checkpoint instructions.
The next Pi request uses the updated system sections and retains conversation
and tool history. Arbitrary instruction, provider or model changes are rejected.

Usage counts must be nonnegative safe integers. A streaming fetch wrapper validates
raw terminal Responses, Messages, Chat Completions and Gemini usage before Pi can normalize absent or negative counters
to zero. Failed or aborted model streams
have unknown terminal spend: the worker emits no terminal usage or checkpoint.
A user-initiated abort reports a recoverable turn failure; the next unguarded turn
can continue. Provider errors are fatal and retire the cloud runner immediately.
Checkpoint export failure also retires the worker. Guarded accounting stays
pending until the existing recovery/accounting contract can settle it; it does
not silently allow the next budgeted turn.

### Regenerating the compatibility definitions

`packages/pi-harness/src/legacy-models.json` retains complete definitions for
previously admitted models that are missing or have a different protocol, endpoint
or supported efforts in the installed SDK. It includes definitions from Pi 0.87.1
and 1.0.4.

When upgrading the SDK, use the preceding engine checkout's admitted catalog and
any retained definitions as the baseline. Install frozen dependencies in both
checkouts, then run this from the upgraded repository root with the absolute
path to the baseline. The check compares the regenerated definitions with the
checked-in JSON. Omit `--check` to print the definitions for review.

```sh
cd packages/pi-harness
node --input-type=module - /path/to/previous-engine-checkout --check <<'JS'
import assert from 'node:assert/strict';
import { existsSync, readFileSync } from 'node:fs';
import { join } from 'node:path';
import { pathToFileURL } from 'node:url';
import { ModelRuntime } from '@earendil-works/pi-coding-agent';
import { InMemoryCredentialStore, getSupportedThinkingLevels } from '@earendil-works/pi-ai';

const root = process.argv[2];
const read = (path) => JSON.parse(readFileSync(join(root, path), 'utf8'));
const importPrevious = (name) => import(pathToFileURL(
  join(root, 'packages/pi-harness/node_modules/@earendil-works', name, 'dist/index.js'),
).href);
const { ModelRuntime: PreviousRuntime } = await importPrevious('pi-coding-agent');
const { InMemoryCredentialStore: PreviousCredentials } = await importPrevious('pi-ai');
const create = (Runtime, Credentials) => Runtime.create({
  credentials: new Credentials(), modelsPath: null, refreshOnCreate: false,
});
const previous = await create(PreviousRuntime, PreviousCredentials);
const current = await create(ModelRuntime, InMemoryCredentialStore);
const admitted = read('packages/harness-catalog/src/pi-models.json');
const retainedPath = 'packages/pi-harness/src/legacy-models.json';
const retained = existsSync(join(root, retainedPath)) ? read(retainedPath) : {};
const efforts = (model) => getSupportedThinkingLevels(model).filter(
  (level) => !['off', 'minimal'].includes(level),
);
const endpoint = (model) => model.baseUrl.replace(/\/$/, '');
const compatibility = {};
for (const [provider, models] of Object.entries(admitted)) {
  for (const id of Object.keys(models)) {
    const old = retained[provider]?.[id] ?? previous.getModel(provider, id);
    if (!old) throw new Error(`Missing previous model definition: ${provider}/${id}`);
    const native = current.getModel(provider, id);
    if (!native || native.api !== old.api ||
        endpoint(native) !== endpoint(old) ||
        JSON.stringify(efforts(native)) !== JSON.stringify(efforts(old))) {
      (compatibility[provider] ??= {})[id] = old;
    }
  }
}
if (process.argv.includes('--check')) {
  assert.deepEqual(compatibility, JSON.parse(readFileSync('src/legacy-models.json', 'utf8')));
  const count = Object.values(compatibility).reduce(
    (total, models) => total + Object.keys(models).length,
    0,
  );
  console.log(`Verified ${count} retained Pi model definitions`);
} else {
  process.stdout.write(JSON.stringify(compatibility, null, 2) + '\n');
}
JS
```

## Validation

Tests run the installed Pi SDK against local native protocol fixtures for OpenAI, Anthropic, DeepSeek, Gemini and ZAI across the
server worker, shared HTTP/SSE bridge and built self-hosted child process. They
also continue native 0.87.1 checkpoints for all five providers and a native
1.0.4 Anthropic checkpoint. The 0.87.1 cases also run through the built self-hosted
child process. They cover managed tools, approvals, callback conversion, usage, native recovery and
request-budget denial. Anthropic cache creation retains its five-minute/one-hour split; DeepSeek cached input is counted separately from uncached input. PostgreSQL tests cover deployment admission, durable
receipts, ownership fences and Registry accounting for both SDKs.

The real-model E2E selector accepts `ORCA_E2E_AGENT_HARNESS=pi_sdk` for both
`pnpm e2e:agent` and `pnpm e2e:agent:sandbox`. The stack workflow includes a Pi
PostgreSQL leg using `anthropic/claude-sonnet-4-6` in both separate and colocated
modes. The Pi leg uses a Gateway image with native Pi provider routing. These suites require the running stack and Anthropic credentials. Kafka
uses Claude SDK and Pulsar uses Codex SDK with OpenAI.
