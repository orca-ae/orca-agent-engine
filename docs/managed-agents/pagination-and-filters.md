# Pagination and Filters

This inventory documents current behavior. It is not a normalization plan.
P2 tests should lock existing supported behavior and document accepted-but-
ignored parameters instead of changing public API semantics.

## Summary

| Route family      | Envelope                                                               | Supported query params                                                                                                                                                                                                                                             | Current limitation                                                                                                                                                                                           |
| ----------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Agents            | `{ data, next_page }`                                                  | Top-level list and `GET /v1/agents/:id/versions` support `limit` and `page`.                                                                                                                                                                                       | Top-level list applies `include_archived`, `created_at[gte]` and `created_at[lte]`; no other filter is offered.                                                                                              |
| Environments      | `{ data, next_page }`                                                  | Top-level list supports `limit` and `page`.                                                                                                                                                                                                                        | Top-level list applies `include_archived`; no other filter is offered.                                                                                                                                       |
| Sessions          | `{ data, next_page, prev_page }` (`prev_page` omitted for `orca-beta`) | Session list supports `limit`, opaque `page`, agent/version, created-at, deployment, archived, memory-store, order, and status filters. ## Compatibility notes

- Where present, `next_page` is always either a cursor string or `null`.
- Vault and credential list routes use `include_archived=false` by default and
  exclude archived rows unless explicitly requested.
- Invalid positive-integer parameters and cursor/filter mismatches return 400
  through the Claude error envelope.
- Skill list cursors carry the exact PostgreSQL microsecond ordering key and
  are scoped to the authenticated workspace and original `source` filter.
  Clients must treat them as opaque.
- Session cursors are opaque and are scoped to their original sort direction.
  Clients must not construct or decode them. The server rejects an explicit
  `order` that conflicts with the cursor instead of silently changing traversal
  direction.
- Routes that ignore query params should remain documented as limitations until
  a separate compatibility-layer plan normalizes `page`, `limit`, and filters.
- Files intentionally use Anthropic's older cursor scheme (`after_id` /
  `before_id` with `first_id` / `last_id`) rather than the newer `page` /
  `next_page` envelope used by most Managed Agents list endpoints.
